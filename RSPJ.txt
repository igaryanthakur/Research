## 6. PROBLEM STATEMENT
Several studies apply SHAP or LIME to explain malicious URL classifiers, but most pick one method without comparing it against another. When two explainers give different reasons for the same prediction, an analyst has no basis for deciding which to trust. Prediction overhead is also raised as a concern, yet the time cost of generating explanations is rarely measured. This project examines how consistently SHAP and LIME explain the same malicious URL classifier, and how their computational costs compare.

## 7. RESEARCH QUESTIONS AND HYPOTHESES
RQ1: How well do SHAP and LIME agree on the most influential features for the same URL predictions?
RQ2: Does agreement differ across URL classes (benign, phishing, malware, defacement)?
RQ3: How do SHAP and LIME differ in per-prediction explanation time?
H0-1: No meaningful difference between top-k features of SHAP and LIME (agreement high). H1-1: They differ significantly for a considerable share of predictions.
H0-2: Agreement does not vary across classes. H1-2: It varies significantly.
H0-3: Per-prediction explanation time is the same. H1-3: It differs significantly.
The agreement threshold (e.g. mean Jaccard < 0.7 = considerable disagreement) must be fixed BEFORE running experiments and stated in the report.

## 10. TECHNICAL PLAN
- Data: 4-class URL dataset (benign, phishing, malware, defacement), likely the ~651k-URL Kaggle dataset used in Paper 1. NOT YET VERIFIED: source, licence, label quality. Remove duplicate URLs before splitting.
- Features (~20, plain Python, no external lookups): URL length, host length, digit count, special-character counts (@ - _ ? = %), subdomain count, IP-in-host, HTTPS, entropy, path depth.
- Models: stratified 80/20 split; class weights if imbalanced; compare on accuracy, precision, recall, macro-F1; pick the best (likely XGBoost or RF). Tree models chosen because shap.TreeExplainer is fast and exact on them and prior work reported strong results with them. SVM, KNN and deep learning excluded for time and slow explanations.
- Explanations: shap.TreeExplainer and LimeTabularExplainer on a random 500-1000 test sample; explain the model's PREDICTED class for both; fix LIME random_state; save results to disk.
- Agreement: top-k (start k=5) features from each explainer; Jaccard and Spearman per URL; average overall and per class.
- Timing: time.perf_counter() per URL for both; note that SHAP batching favours SHAP.
- Stats: Wilcoxon or paired t-test for timing; Kruskal-Wallis for agreement across classes (scipy).
- Compute: normal laptop is enough.
