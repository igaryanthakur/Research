Day 1 produced an academically defensible baseline:

The Day 2 objective was to improve this baseline without restoring the raw

Work was limited to:

  2. comparing Logistic Regression, Random Forest and XGBoost;

2. REFERENCE STUDY REVIEWED
--------------------------------------------------------------------------------

Read:
  Poddar, Chowdhury, Dwivedi and Mukkamala,
  "Data Driven based Malicious URL Detection using Explainable AI,"
  IEEE TrustCom 2022.

Paper methodology:
  - same 651,191-URL, four-class dataset;
  - 21 URL features;
  - random 70/30 train/test split;
  - level-0 LightGBM, Gradient Boosting, XGBoost and Random Forest;
  - Random Forest final estimator and stated five-fold stacking;
  - reported stacked accuracy 97%;
  - ALE explanations rather than SHAP.

Useful paper-inspired ideas:
  - first-directory length;
  - TLD length;
  - embedded-link indicator;
  - suspicious-token flag/count;
  - shortened-URL indicator.

Features deliberately NOT copied:
  - count-http;
  - count-https;
  - count-www.

Reason:
  Day 1 proved that scheme and www formatting depends strongly on the source
  class. Reintroducing these fields would increase the score but make the model
  learn the dataset collection process.

Stacking was also rejected for this stage because it is outside the required
three-model comparison, the paper does not specify enough details for exact
reproduction, and it would unnecessarily complicate later explanation work.


--------------------------------------------------------------------------------
3. PLAN AND RULES FIXED BEFORE EXECUTION
--------------------------------------------------------------------------------

A separate V2 pipeline was planned so that all V1 code and saved results stayed
unchanged.

Candidate eligibility:
  - validation accuracy > 0.8463;
  - validation macro-F1 >= 0.8254;
  - recall for defacement, malware and phishing >= 0.70;
  - a malicious-class recall drop > 0.05 versus V1 is permitted only when
    macro-F1 >= 0.8354 (V1 + 0.01).

Selection among eligible candidates:
  1. highest validation macro-F1;
  2. macro-F1 values within 0.005 are treated as near-tied;
  3. among near ties, higher validation accuracy;
  4. then higher minimum malicious-class recall;
  5. then lower fitting time.

Other fixed rules:
  - unseen-host validation metrics are diagnostic only;
  - test data is not used for feature or model selection;
  - the first 24 V2 columns must exactly equal V1 output;
  - suspicious words must match whole tokens;
  - the final test stage refuses to run when test_metrics.json already exists;
  - all trials use random seed 42.

Memory rule:
  About 5.3 GB RAM was free before tuning. Random Forest trials were allowed a
  3 GB projected tree-memory budget. Trees were grown in chunks of 50 and were
  capped/stopped when necessary. A unit test confirmed that fixed-seed chunked
  fitting gives the same probabilities as fitting all trees in one call.

5. V2 FEATURE ENGINEERING
--------------------------------------------------------------------------------

V1 features retained (24):
  - URL, hostname, path and query lengths;
  - counts of dot, hyphen, underscore, slash, ?, =, @, &, %, digits, letters;
  - digit and special-character ratios;
  - subdomain count, path depth and query parameter count;
  - IP-host, port and percent-encoding indicators;
  - Shannon entropy.

New structural block (12):
  - counts of colon, hash, plus, tilde and semicolon;
  - first-directory length;
  - longest path-segment length;
  - TLD length;
  - hostname-label count;
  - maximum hostname-label length;
  - fragment length;
  - embedded // count after the hostname.

New lexicon block (3):
  - exact suspicious-token count;
  - exact known-shortener host indicator;
  - punycode indicator.

Total generated V2 features: 39.

Important safety decisions:
  - all input comes from the normalized URL;
  - no scheme/HTTP/HTTPS/www indicator;
  - no label or source feature;
  - no WHOIS, DNS, page fetch or other network call;
  - malformed URLs must still produce finite deterministic values.

--------------------------------------------------------------------------------
8. FEATURE-BLOCK ABLATION
--------------------------------------------------------------------------------

The unchanged V1 Random Forest was used so that only input features changed.

  feature set           n     val accuracy   val macro-F1
  V1                    24       0.8459          0.8254
  V1 + lexicon          27       0.8481          0.8276
  V1 + structural       36       0.8839          0.8656
  full V2               39       0.8824          0.8641

Decision:
  Lock V1 + structural = 36 features.

Finding:
  The structural block caused the major gain. The token, shortener and punycode
  block added little and slightly reduced the full-set result, so it was not
  used for model tuning.

Colon check:
  Defacement URLs have more colons on average than benign URLs. Manual examples
  showed Joomla paths such as catid=26: and IP:port URLs. This is genuine URL
  content rather than an explicit scheme flag. However, repeated templates may
  still identify campaigns or sources, so the safe claim is "no known explicit
  source-format leakage features," not "no leakage."


--------------------------------------------------------------------------------
9. MODEL TUNING
--------------------------------------------------------------------------------

Logistic Regression:
  - C = 0.1, 1, 10;
  - no, square-root-balanced and fully balanced weights;
  - StandardScaler and max_iter=2000.

Random Forest:
  - coarse: 300 trees;
  - depth 25 or unlimited;
  - minimum leaf size 1, 3 or 5;
  - no or square-root-balanced weights;
  - selected refinements up to 500 trees;
  - sqrt or 0.5 feature sampling;
  - one exact V1-style balanced control.

XGBoost:
  - depth 6, 8 or 10;
  - learning rate 0.05 or 0.1;
  - no or square-root-balanced weights;
  - subsample 0.8;
  - column subsample 0.8;
  - maximum 1,000 trees;
  - validation-log-loss early stopping after 50 non-improving rounds.

Every trial recorded:
  - accuracy;
  - macro and weighted precision/recall/F1;
  - per-class precision/recall/F1/support;
  - confusion matrix;
  - fit and prediction time;
  - unseen-host validation accuracy and macro-F1;
  - model parameters, class weights and trial status.

Completed trials were appended immediately and skipped if their trial ID was
already present, making the run resumable.

--------------------------------------------------------------------------------
14. PHISHING TRADE-OFF
--------------------------------------------------------------------------------

V2 improved phishing precision from 0.5961 to 0.7451 but reduced phishing
recall from 0.7924 to 0.7559.

Concrete error changes:
  benign incorrectly predicted as phishing:
    V1 6,192 -> V2 3,065 (3,127 fewer false alarms)

  phishing incorrectly predicted as benign:
    V1 2,009 -> V2 2,835 (826 more missed phishing examples)

Interpretation:
  The model is much less likely to raise a false phishing alarm, but it misses
  more real phishing URLs. It is incorrect to claim that V2 improved every
  class. It improved overall performance and phishing precision, not phishing
  recall.

================================================================================
DAY 2 SUMMARY
================================================================================

Day 2 built an isolated V2 pipeline while preserving V1. Fifteen candidate
lexical features were added and tested in structural and lexicon blocks. The
12 structural additions raised the unchanged Random Forest validation accuracy
from 0.8459 to 0.8839; the lexicon block contributed almost nothing and was
excluded.

Logistic Regression, Random Forest and XGBoost were then compared with fixed
eligibility and selection rules. The selected model was square-root-balanced
XGBoost with 36 features, depth 10, learning rate 0.1 and 636 trees.

On the untouched test set, evaluated once, V2 achieved 0.9089 accuracy and
0.8863 macro-F1, compared with V1's 0.8471 and 0.8269. V2 is also much smaller
(55.9 MB versus 565 MB). Phishing recall fell by 0.0365, and unseen-host
macro-F1 remains only 0.6311, so these limitations are explicitly retained.

The classifier stage is now strong enough to freeze. The next project stage is
the planned SHAP-versus-LIME agreement and timing experiment.
