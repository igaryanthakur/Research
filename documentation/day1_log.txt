2. DECISIONS (FIXED BEFORE SEEING XAI RESULTS)
--------------------------------------------------------------------------------

Data
  D1. Normalize every URL before feature extraction: strip whitespace, remove
      the scheme (anything matching "scheme://") and one leading "www."
      (case-insensitive). Paths are NOT lowercased or rewritten.
  D2. Remove every normalized URL that carries more than one label (all
      copies), instead of guessing the right label.
  D3. Keep one row per normalized URL (first occurrence; its raw string is kept
      for the raw-URL ablation).
  D4. Stratified 70/15/15 train/validation/test split, random_state = 42.
      Split saved inside artifacts/clean.parquet so every script uses it.
  D5. No hostname-grouped split (would change the agreed experiment); hostname
      overlap reported as a limitation and analysed separately.

Features
  D6. Lexical features only, no network calls (no WHOIS, DNS, page content).
  D7. Primary model has NO https flag and NO has-scheme flag.

Models
  D8. Compare Logistic Regression, Random Forest and XGBoost.
  D9. Select by validation macro-F1 (classes are imbalanced); report accuracy,
      macro precision/recall/F1 and per-class recall.
  D10. Class imbalance: class_weight='balanced' (LR),
       'balanced_subsample' (RF), balanced sample weights (XGBoost).
  D11. Random Forest capped (200 trees, max_depth 25, min_samples_leaf 5) to
       keep model size and TreeSHAP time manageable.
  D12. Refit the selected configuration on train+validation, evaluate once on
       test. 95% accuracy treated as a target, not a requirement.

XAI (fixed now, before running explanations)
  D13. k = 5 (top-5 features).
  D14. Sample: 500 test URLs, 125 per PREDICTED class, seed 42, sampled from
       all test predictions with a saved "correct" flag.
  D15. Considerable disagreement = mean top-5 Jaccard < 0.50.
       The earlier 0.70 threshold was rejected: with two 5-feature sets, even
       4 shared features give 4/6 = 0.667.
  D16. Spearman correlation over the full vector of absolute importances
       (all 24 features); NaN recorded when a vector is constant.
  D17. LIME: default quartile discretization (discretize_continuous=True),
       random_state 42, num_samples 2000 initially, labels = predicted class,
       weights via as_map(). Non-discretized mode was rejected because, with
       sample_around_instance=False, LIME would sample around the training mean
       rather than around the URL being explained.
  D18. SHAP: TreeExplainer on the final model; explain the predicted class.
  D19. Timing per URL with time.perf_counter(), after warm-up, excluding
       loading and disk writes. Caveat: per-instance TreeSHAP vs
       perturbation-based LIME is the measured setup, not a universal claim.
  D20. Statistics: Wilcoxon signed-rank (timing), Kruskal-Wallis (Jaccard
       across predicted classes).

3. PROBLEMS DISCOVERED AND CORRECTIONS
--------------------------------------------------------------------------------

P1. Formatting artifact in the dataset (serious).
    Found: scheme/www/https presence depends on class source (table above).
    Risk : inflated accuracy, and artifact features could dominate both SHAP
           and LIME, artificially raising their agreement (contaminating RQ1).
    Fix  : normalization (D1) + no scheme flags in the primary model (D7).
    Proof: three-way ablation (section 5) shows ~9.3 accuracy points come
           from raw formatting.

P2. Label noise exposed by normalization.
    Found: 4,047 normalized URLs had two labels (raw file showed only 6).
           All are benign vs phishing:
             - 4,018: copy WITH a scheme labelled phishing, copy WITHOUT a
                      scheme labelled benign
             - 29   : copy WITH "www." labelled phishing, copy WITHOUT "www."
                      labelled benign
           Example: http://000067d.rcomhost.com/ssl/dk/sesion/confirm/...
           /DANSKEBANK-DK/FRAUD/MEMBER-ID/... is phishing, but the scheme-less
           copy is labelled benign.
    Fix  : all 8,230 rows of these URLs removed (D2).
    Correction: I first wrote that "every" conflict was http vs no-scheme;
           the student's check showed 29 are www-based. Documented correctly
           now.

P3. Malware class shrank from 32,520 to 23,593.
    Cause: duplicates after normalization (the same malware URL listed with
           different schemes / www), not conflicts (all conflicts were
           benign/phishing).

P4. Feature count misreported.
    I reported 25 features; correct count is 24 (primary) and 26 (raw +
    is_https + has_scheme). Corrected; n_features is now saved in the
    ablation CSV.

P5. Two-way ablation was not feature-matched (raw run also added two flags).
    Fix: three-way ablation (normalized/24, raw/24, raw+flags/26).

P6. Hostname overlap: ~74% of test URLs share a hostname with training.
    Fix: added seen vs unseen hostname subgroup evaluation (no retraining).
    Overlap measured against train+validation hosts, because the final model
    was refit on train+validation.

P7. Unseen-host subgroup has only 21 defacement URLs (14,275 in seen-host).
    Its macro-F1 (0.6089) and defacement recall (1.0) are unreliable;
    compare per-class recall with supports instead.

P8. PowerShell piping/quoting error when chaining prepare.py with
    Select-String; prepare.py was re-run alone. No effect on results.

P9. Final Random Forest is 565 MB on disk (artifacts/ excluded from git).
    Acceptable on this laptop; note that check.py reloads it on every call.

================================================================================
DAY 1 SUMMARY
================================================================================
Built and ran a reproducible pipeline (load -> normalize -> clean -> split ->
24 lexical features -> LR/RF/XGBoost -> validation selection -> single test
evaluation -> saved model), with 12 passing unit tests and all intermediate
artifacts saved.

Key finding: the popular 651k malicious URL dataset leaks its labels through
URL formatting. Normalizing scheme and "www." exposed 4,047 contradictory
labels and dropped test accuracy from 94.0-94.7% (raw) to 84.7% (normalized,
macro-F1 0.827). This is the honest baseline for the XAI study, and the
artifact itself is a reportable contribution.

Further, 75% of test URLs share a hostname with training data; on unseen
hostnames accuracy falls to 77.9%, with benign and malware recall dropping
most. These are stated limitations.

Selected model: Random Forest (200 trees, depth 25, min leaf 5, balanced
subsample weights). XAI protocol (k=5, 500 URLs, Jaccard < 0.50) fixed before
any explanation was generated.
