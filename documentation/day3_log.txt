Finding:
  The main performance increase came from the 300 character n-gram fields.
  XGBoost rose from 0.9216 accuracy with the 48 lexical fields to 0.9445 with
  all 348 fields. The ensemble added a smaller improvement.

Selection rule:
  - maximize validation macro-F1;
  - values within 0.005 are near-tied;
  - among near ties prefer accuracy, then minimum malicious recall, then time.

Winner:
  stack_lr_xgb_lgbm

Tie detail:
  The soft vote has slightly higher macro-F1 (0.9309 vs 0.9307) and phishing
  recall (0.8132 vs 0.7961). The stack wins under the fixed near-tie rule
  because it has higher accuracy (0.9463 vs 0.9458).

11. REPRODUCIBILITY FIX AND VERIFICATION
--------------------------------------------------------------------------------

Problem:
  The first V3 verification implementation predicted the first 2,000 feature
  rows but compared them with the first 2,000 saved test predictions. Test rows
  are not the first sequential dataset rows, so the assertion failed.

Correction:
  stage_verify now:
    1. reads test_predictions.csv first;
    2. gets its saved row_id values;
    3. selects matching rows from features_v3_full by index label;
    4. rebuilds base and meta-model probabilities;
    5. compares them with the corresponding saved probabilities.

No model was retrained and no result file was regenerated.

Verification command:
  python train_v3.py verify

Verified output:
  "Verified: final model reloads and matches saved test probabilities."

Result:
  exit code 0

CPU portability:
  The saved XGBoost model was fitted with CUDA enabled. On a machine without a
  visible GPU, XGBoost warns that it is changing to CPU. Verification still
  reproduces the saved probabilities within tolerance.

13. V3 AND THE EXISTING SHAP/LIME RESULT
--------------------------------------------------------------------------------

V2 XAI target:
  one XGBoost model
  36 human-readable fields
  exact XGBoost TreeSHAP available
  same model callable by LIME

V3 target:
  XGBoost + LightGBM probabilities
  Logistic Regression meta-model
  348 fields, including 300 correlated character n-grams

Technical consequence:
  TreeSHAP can explain either V3 base tree model, but not the complete stacked
  prediction through one direct TreeSHAP call. Explaining only one base would
  not explain the final V3 decision.

LIME consequence:
  LIME can call the full stack, but tabular perturbations independently change
  correlated n-gram fields. Those vectors may not represent any real URL and
  would be hard to interpret. V2 LIME already has weak mean local R2 (0.156).

Current lowest-risk reporting option:
  - V3 is the strongest classification model.
  - V2 is the explicitly named explanation model.
  - Existing V2 SHAP/LIME values are never presented as V3 explanations.

This wording decision remains to be confirmed before final report submission.


--------------------------------------------------------------------------------
14. LIMITATIONS ADDED FOR V3
--------------------------------------------------------------------------------

L1. The test partition was reported in earlier iterations, so V3 is not a
    completely independent confirmatory test.
L2. 75.3% of test URLs share a hostname with train+validation.
L3. Character n-grams may encode campaigns, templates or source-specific text.
L4. The brand-domain approximation is not Public Suffix List aware.
L5. CatBoost was capped and the model-family search was intentionally bounded.
L6. Random Forest was not evaluated with V3 features.
L7. The V3 stack is harder to explain directly than the V2 single XGBoost.
L8. Dataset licence/provenance and external-dataset validation remain open.

================================================================================
DAY 3 SUMMARY
================================================================================

V3 reused the normalized 631,179-row dataset and fixed split from V2. It added
nine entropy/brand lexical fields and 300 train-fitted character TF-IDF
3/4-grams, producing 348 inputs. XGBoost, LightGBM and CatBoost were compared,
followed by soft voting and three-fold out-of-fold Logistic Regression
stacking.

The selected XGBoost-LightGBM stack achieved validation accuracy 0.9463 and
macro-F1 0.9307. On the held-out random-split test partition it achieved
accuracy 0.9485 and macro-F1 0.9338. All displayed class metrics improved over
V2; phishing F1 rose from 0.7504 to 0.8304.

Unseen-host accuracy improved from V2's 0.8357 to 0.8881, but remains below
the 0.9683 seen-host result. Host overlap, n-gram memorization and the unstable
21-example unseen defacement subgroup remain limitations.

The V3 artifact reload verification was corrected to select feature rows by
saved test row_id. It now passes without retraining or changing results. The
complete suite also passes: 55 tests in 1.99 seconds.

V3 is the strongest classifier, but its stacked structure and 300 correlated
n-gram fields make direct SHAP/LIME comparison substantially less defensible.
The completed quantitative XAI evidence remains valid for the explicitly named
V2 XGBoost explanation model. Final report wording must preserve this boundary.
